# LESSONS.md — 经验教训沉淀

> 从 LLM Perf Bench 开发过程中提取的关键教训，避免同类错误重犯。

## L-001: i18n 键必须双词典同步
**场景**：批量脚本添加新 UI 字段时，因断言中断只写入了一个语言的词典，另一语言缺失导致界面显示原始键名（如 "field.repeat"）。
**教训**：添加 i18n 键时，必须在 zh 和 en 两个词典中都添加。批量脚本要分段写入（每段独立 assert + save），避免一次失败全部丢失。
**预防**：添加后立即用 `t(key)` 验证非空，或在 jsdom 测试中加键覆盖检查。

## L-002: canvas clearRect 导致导出 PNG 透明孔
**场景**：图表用 `clearRect` 清除画布，导致导出 PNG 的图表区域变为全透明，看图器渲染为黑色块。
**教训**：导出 PNG 的画布永远用 `fillRect` 填充不透明背景色，不用 `clearRect`（它清除为透明而非背景色）。
**预防**：在 draw 函数开头统一 `ctx.fillStyle = surface; ctx.fillRect(0, 0, W, H)`。

## L-003: 不确定度带的数据源必须与中位数一致
**场景**：中位数用服务端计时（Ⓢ，5000+ tok/s），带用客户端值（2000-3000 tok/s），导致带画在中线以下的错误位置，形成大面积色块。
**教训**：多轮聚合时，min/max 必须从与 median 相同的数据源计算。如果 median 用 serverTimings，min/max 也必须用 serverTimings。
**预防**：在聚合阶段统一存储 `xxxMin`/`xxxMax` 字段（与 median 同源），图表直接读取。

## L-004: CSS nth-child 在动态内容下不可靠
**场景**：用 `nth-child(2)` 给 grid 第二列加左边框，但 DOM 结构变化后选择器不匹配。
**教训**：Grid/Flex 布局的分隔线用 `gap: 1px` + 容器 `background: var(--border)` + 子元素 `background: var(--surface)` 方案，不依赖 nth-child。
**预防**：面板分隔线一律用 gap+bg 技术。

## L-005: 代理必须发 Cache-Control: no-cache
**场景**：浏览器缓存了旧版 HTML（启发式缓存），用户做了普通刷新但拿到的仍是旧 JS，新功能"不生效"。
**教训**：静态文件代理必须发送 `Cache-Control: no-cache` 头，强制浏览器每次刷新都校验新鲜度。
**预防**：在代理的 `end_headers` 中统一注入。

## L-006: 双 Y 轴是可视化反模式
**场景**：速度图用双 Y 轴分别放 prefill 和 decode，用户反映看不懂、容易混淆。
**教训**：Datawrapper/Tableau/Grafana 共识——双轴暗示虚假关联。应拆为共享 X 轴的单轴面板（llama.cpp pp/tg 分离惯例）。
**预防**：每个面板一个指标一个轴一个单位。

## L-007: 首个测试点失败即停止
**场景**：配置错误（如旧模型名）时，7 个测试点全部逐个报错跑完，浪费用户时间。
**教训**：首点（最短输入）失败意味着配置有问题，后续点只会重复同样的错。首点失败（非 ctx/非中止）→ 立即停止 + 引导。
**预防**：`isFatalConfigError(row, isFirstPoint)` 中 `isFirstPoint=true` 时任何非 ctx 错误都视为致命。

## L-008: 空态引导卡应在首次数据后永久隐藏
**场景**：每次点击"开始测试"都会清空数据→空态引导卡重新出现，用户看过一次就不需要再看。
**教训**：空态引导只服务首次访问。加会话级标记 `heroShown`，首个数据点到达后永久隐藏。
**预防**：所有"仅首次"的 UI 状态都应加 session 标记。

## L-009: toast 提示的"仅一次"逻辑要覆盖所有触发点
**场景**：钳制提示 toast 有两个触发点（开测前检查 + 运行中反应式钳制），只给一个加了 `clampToastShown` 标记，另一个仍然每次弹。
**教训**：grep 所有 toast 调用点，确保共享同一个 session 标记。
**预防**：添加"仅一次"逻辑时，搜索所有 `toast(` 调用确认覆盖。

## L-010: Chrome canvas 支持 8 位 hex 颜色
**场景**：用 `col.line + '22'` 拼接 8 位 hex（#RRGGBBAA）做半透明填充，在 Chrome 中正常工作。
**教训**：Canvas 2D API 支持 4/8 位 hex。`#60a5fa22` = 13% alpha 蓝色。但要注意如果 col.line 有空格或非 hex 格式，拼接后会变成无效颜色，Canvas 会保留上一个 fillStyle。
**预防**：确保从 getComputedStyle 获取的值经过 .trim()，且格式为纯 hex。

## L-011: 浏览器级测试套件会随页面演进"静默漂移"，跑之前先对齐
**场景**：bench_browser_test.js 长期不可运行（/tmp 环境被清 + 页面已演进：路径迁到 /src/、chip 改用 data-backend、canvasSpeed 被 5 面板替代、快速模板从 3 点变 7 点）。环境恢复后发现还有 4 处选择器/断言漂移，首轮跑挂 3 处。
**教训**：测试环境的可复活性 = npm 依赖 + 浏览器缓存 + 系统库三者齐备。playwright-core 版本必须精确匹配 `~/.cache/ms-playwright/chromium-<rev>`（如 1117 → playwright-core@1.44.0，unpkg 查各版本 browsers.json）；headless chromium 缺 libatk 等系统库时用 `sudo node <playwright-core>/cli.js install-deps chromium`。选择器漂移要逐个对照当前页面标记修复，不能绕过断言。
**预防**：测试与页面标记同步修改；套件不可跑的状态本身就该当作 bug 修复，而不是跳过。

## L-012: 语言相关截图证据必须强制 locale，否则"中文截图"实为英文
**场景**：无头浏览器默认 navigator.language=en，localStorage 无 lbp.lang 时页面回落英文——首轮 6 张标注 "zh" 的证据截图实际全是英文界面，二审才发现。
**教训**：截语言相关证据前用 `context.addInitScript(() => localStorage.setItem('lbp.lang','zh'))` + `locale:'zh-CN'` 显式强制；截图文件名 locale 标签要与实际 UI 语言一致。
**预防**：截图脚本里加断言：首个 dt 文本 === '接口协议' 再落盘。

## L-013: gap+bg 分隔网格的"尾部空洞"只有 flex-wrap 能彻底避免
**场景**：摘要卡片网格首版用 `repeat(auto-fit, minmax(190px,1fr))`：auto-fit 只收拢**完全空置**的轨道，12 项落在 7 列时尾行 5 项，尾部 2 个槽位露出容器 border 色背景，形成灰色空洞块。
**教训**：条目数量动态（5–12）的分隔网格，用 `display:flex; flex-wrap:wrap` + 子项 `flex:1 1 <min>px; min-width:0`——每行由既有条目撑满，按构造不可能出现空洞；固定 4 张的 KPI 卡才适合固定列 grid。
**预防**：动态条目 + gap+bg 分隔线模式 → 首选 flex-wrap；验证时专门断言"最后一个条目右缘 === 容器右缘"。

## L-014: 用户说"参考 X 的样式"时，照抄 X 的构造，不要用"设计师更好的方案"替代
**场景**：摘要条连续三轮被用户否决：①等宽拉伸卡+flex-grow（空壳/孤儿全宽卡）②内容自适应卡（1:3.7 宽度参差、分隔线无韵律）③统一列宽无分隔线 airy 网格（左对齐文字在等宽格内仍显参差）。用户最终一句话点破："数一下多少段内容，均分两行，自适应边框，文字居中——比你现在这样强百倍"，即**完全复用页面里已被接受的 KPI 卡构造**。
**教训**：用户指了参照物（stat-cards）就意味着认可它的全部构造要素：均分、通栏分隔线、居中。此时最短路径是照抄构造再适配条目数，而不是引入自认为更精致的新范式（无分隔线/内容自适应等）。三轮返工本可一轮通过。
**预防**：改版前把用户给的参照物拆成构造要素清单（列数策略/分隔线/对齐/边框），逐项对齐；有歧义先确认，不要自由发挥。

## L-015: flex 项上的 auto margin 会吃掉剩余空间，flex-grow 随之失效
**场景**：给 `.main-col`（flex:1）同时加 `max-width:1600px; margin-inline:auto` 想实现"占满但居中"——结果主列冻结在内容宽度（1412px），grow 完全不生效：CSS Flexbox 规范中 auto margin 优先于 grow/shrink 分配剩余空间。
**教训**："限宽 + 居中"不要放在 flex 子项自身；把 `width:100%; max-width:X; margin-inline:auto` 放到该子项内部的**块级内容**上，flex 子项继续正常 grow。同理，收起态组件（width:0）仍会贡献 gap——间距应改为随收起归零的 margin。
**预防**：flex 布局里需要居中限宽容器时，优先"外层 flex 占满 + 内层块级 auto margin"两层结构；验证时断言左右 gutter 相等（对称性数值化）。

## L-016: 引导/警示 UI 必须有完整的生命周期——每个"显示"都要枚举对应的"消失"
**场景**：配置引导横幅+字段红框只在"用户手动编辑字段"和"下次校验通过开测（仅横幅）"时清除；测试成功完成/中止后从不清除，且快捷 chip、测试连接自动填充走程序化设值（无 input 事件）绕过清理监听——提示无限残留，用户以为是新优化引入的回归。
**教训**：给警示 UI 加"显示"时必须同时枚举全部消失时机：(a) 用户修正（含一切程序化修改途径——统一走事件而非裸赋值）；(b) 生命周期事件（开测校验通过、出现成功结果证明配置可用）。"裸 value 赋值 + 手动调 saveCfg"的旁路是清理链断裂的典型根源。
**预防**：警示 UI 变更后写一个"错误→修复（含程序化途径）→成功"的端到端回归场景（[11b] 模式）。

## L-017: 离屏 canvas 导出的高度预算必须与绘制共享同一组常量（measure-first）
**场景**：导出 PNG 改版（整幅堆叠图表 → 5 面板网格）后，`totalH` 预算与绘制各改各的：预算仍按旧布局 `chartBlock*2`=1592px 预留、绘制侧 y 又双重前进 1502px（实际仅 360px）——图表与表格间出现 1142px 空白带（占整图 55%），整图 1:1.6 竖条；且 headH 预算 174 vs 绘制实耗 202 的 28px 漂移被图表超额预留掩盖，两处独立漂移互相遮蔽，存活 20+ 轮迭代无人发现（页面渲染不经过该函数，浏览器测试只断言 PNG>30KB）。
**教训**：手绘 canvas 报告的 section 高度要"先测量后绘制"——所有高度进一个常量对象，`totalH=Σ常量`，绘制严格消费同一对象；任何"预留量"（如旧布局的 chartBlock）在改版时必须连同删除，死代码（drawChartBlock 引用不存在的 legendInfo）是漂移的藏身处。另外回归测试不能只断言"文件有内容"，必须断言布局不变量（宽度精确值/高度区间/像素级空白带扫描/主题间高度一致）。
**预防**：canvas 导出类功能配一个像素断言测试（导出图回灌 canvas 扫描连续同色行），空白带/溢出即刻暴露；改版时 grep 旧常量名（chartBlock/CH）确认零残留。

## L-018: "补齐词典漂移键"之前先审引用——缺的键可能是本就该死的键
**场景**：TASKS T5 要求"ZH 补 `a11y.collapseShort` 以对齐 EN 词典"。照做后全量引用审核才发现：该键在 EN 侧也零引用（UI 用的是 `a11y.collapse`）——它是旧版折叠按钮遗留死键，正确动作是"双侧删除"而非"补齐对齐"。补齐等于把死代码又复制了一份，且让"键数一致"的假象掩盖了真正的清理需求。
**教训**：i18n 键漂移的处理顺序必须是"先审两侧引用 → 活键补齐 / 死键删除"，键数对称是结果而不是目标。同理适用于任何"按清单补齐"类任务：清单可能描述的是早已被重构掉的旧功能。
**预防**：词典维护配一个"死键扫描"步骤（枚举动态前缀后比对引用），补键与删键走同一个审核脚本；T13 的清理脚本可直接复用。
